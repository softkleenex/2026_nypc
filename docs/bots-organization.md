# Bots and Log Organization

이 문서는 `bots/` 폴더의 보관 규칙을 정리한 색인이다. 실제 폴더 안의 운영 규칙은 `../bots/README.md`와 동일하게 유지한다.

## 제출 단위

- `숫자.py`: 제출 코드 또는 후보 코드. 현재 작업 공간은 Python 봇을 사용한다.
- `숫자.data`: 선택 데이터 파일. 현재 `bots/` 안에는 `.data` 파일이 발견되지 않았다.
- 같은 번호의 코드와 데이터는 한 제출 후보로 본다. 코드나 데이터가 바뀌면 새 번호를 만든다.

## 로그 종류

- `숫자_nypc_log/`: 제출 직후 NYPC가 제공하는 8개 공식 봇 상대 로그. 공식 샘플 환경의 직접 증거다.
- `user_logs/`: 몇 시간마다 진행되는 중간평가 로그. 상대 매칭은 랜덤성이 있고, 상대 코드도 시간에 따라 바뀔 수 있다.
- `archive/`: 지난 코드 세대, 보존 로그, `logs_backup_*.tar.gz` 백업.

## 현재 루트 상태

- 제출 코드: 전환점 `77.py`, 비교 기준 `90.py`/`91.py`, 개선 후보 `125.py`, 최신 후보 `132.py`-`135.py`가 루트에 있다.
- 공식 로그 폴더: `30`, `45`, `60`, `61`, `62`, `76`, `77`, `78`, `91`, `125`, `143` 세대가 보관되어 있다.
- 유저 로그 폴더: `user_logs/eval14_bot_unknown_20260703_1500`, `eval25_bot62_20260707_1000`, `eval26_bot77_20260707_1500`, `eval28_bot91_20260708_1000`이 보관되어 있다.
- 아카이브에는 `8.py`부터 `88.py` 사이의 이전 후보 일부, 루트에서 정리한 `pre77-root/`, `post77-experiments-92-131/`, `logs_backup_*.tar.gz`가 있다.

## 보관 정책

로그는 재획득이 어렵고 해석이 나중에 바뀔 수 있으므로 삭제하지 않는다. 새 평가를 저장할 때는 원본 로그, 순위 페이지, 요약 파일을 같은 폴더에 두고 백업 tarball을 갱신한다. 로컬 평가 산출물은 `results/`에 두며, 전략 결론을 `docs/workflow-strategy.md` 또는 별도 메모에 남긴 뒤에만 정리한다.
