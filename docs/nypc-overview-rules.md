# NYPC Overview and NEXT NATION Rules

이 문서는 NYPC 대회 개요와 예선 게임 `NEXT NATION` 룰북을 함께 보기 위한 레퍼런스다. 앞부분은 읽기용 안내이고, 아래 두 원본은 그대로 포함했다.

## 핵심 범위

- NYPC 2026 Master 부문은 AI 1:1 대결 유형 문제로 진행된다.
- 예선 라운드는 코드와 선택 바이너리 파일을 제출하고, 대표 답안 기준으로 중간/최종 평가가 진행된다.
- `NEXT NATION`은 최대 200일 동안 본부, 기지, 전사, 금화를 운용하는 점대칭 전장 게임이다.
- 로컬 검증은 `nation-providing/testing-tool.py`와 `tools/`의 평가/분석 스크립트를 사용한다.

## 보존 원칙

대회 안내와 룰북은 전략 판단의 기준 문서다. 날짜, 제한, 처리 순서, 승패 조건은 임의로 바꾸거나 요약만 남기지 않는다.

진행 안내
NYPC 2026은 예선 라운드(Qualification Round, QR)와 본선 라운드(Final Round, FR)로 구성되어 진행됩니다.

Master 부문에서는 AI 1:1 대결 유형의 문제가 라운드마다 한 문제 출제됩니다.

본선 라운드에 출제되는 문제는 본선 전에 공개되지 않지만, 예선 라운드에 출제된 문제와 기본적인 틀을 공유합니다. 따라서 예선 라운드에서 작성한 코드를 부분적으로 본선 라운드에서 활용할 수 있습니다.

예선 라운드
참가 신청 : 2026-06-04 13:00 KST
연습문제 오픈 : 2026-06-04 13:00 KST
예선 라운드 시작 : 2026-06-29 10:00 KST
예선 라운드 종료 : 2026-07-08 22:00 KST
리플레이 제출 마감 : 2026-07-09 23:59 KST
예선 라운드 시작 전에, 연습 문제를 통해 대회에서 사용하는 환경을 미리 테스트할 수 있습니다. 연습 문제의 점수는 총점에 반영되지 않으며, 최종 점수에 영향을 주지 않습니다.

한 라운드 당 하나의 문제가 주어지며, 참가자는 라운드 종료 전까지 문제를 해결하고 답안을 제출해야 합니다.

대회가 종료되고 각 팀은 제출 기한 안에 팀의 문제 풀이 과정을 담은 리플레이를 제출해야 합니다.

본선 라운드
예선 라운드에서 우수한 성적을 거둔 상위 최소 20팀은 8월 29일에 서울에서 열리는 본선 라운드에 참가할 수 있습니다.

자세한 일정은 추후 공지됩니다.

팀원 모두가 본선 라운드 대회장에 도착해야 입장할 수 있습니다.
정해진 입장 마감 시각 이후에는 입장할 수 없습니다.
문제 풀이
참가자는 문제 페이지에서 문제의 설명을 확인하고, 코드와 바이너리(선택) 파일 하나씩을 제출할 수 있습니다.

코드는 1MiB (1048576 바이트) 이하, 바이너리 파일은 10MiB (10485760 바이트) 이하여야 합니다.
제출 즉시 샘플 AI를 통한 채점이 시작되며, 채점이 완료된 후 제출 내역과 결과를 확인할 수 있습니다.
채점 결과는 승/무/패 형태로 표시됩니다.
항상 고정된 입력이 주어집니다.
샘플 AI는 같은 입력에 대해서 같은 전략을 사용합니다.
답안은 여러 번 제출할 수 있으며, 그 중 하나의 대표 답안을 골라 평가에 사용합니다.
예선 라운드
5분에 2번 코드를 제출할 수 있습니다.
5분 이내에 2번 이상 코드를 제출했다면, 추가 제출은 두 번째(마지막) 제출이 아닌, 첫 번째(마지막 전) 제출 시점에서 5분이 경과한 이후에 가능합니다.
제출 간격 및 횟수는 주최측의 사정에 따라 변경될 수 있습니다.
본선 라운드
10초에 1번 코드를 제출할 수 있습니다.
자세한 내용은 아래의 평가 규칙을 확인해 주세요.

실행 및 채점 환경
제출된 모든 코드의 실행과 채점은 다음 환경에서 이루어집니다.

Amazon Web Services의 c7a.2xlarge 인스턴스
AMD EPYC 4세대 기반 커스텀 프로세서
클럭: 3.7 GHz
프로세서 아키텍처: 64 bit
OS: Ubuntu 24.04
이 환경에서 정상적으로 동작하지 않는 코드는 채점되지 않으니 유의하시기 바랍니다. 각 언어별로 사용되는 컴파일러와 구체적인 개발 환경에 대한 정보는 "개발 도구 사용 안내" 페이지를 참고하시기 바랍니다. 시간 및 메모리 제한 초과 여부는 참가자가 제출한 소스 코드가 실행된 프로세스에서 사용하는 자원을 기준으로 판단합니다.

시간은 기본적으로 프로세스가 CPU를 점유한 시간(CPU time)을 측정합니다.
메모리는 프로세스가 사용하는 메모리 양을 측정합니다. 이때, 사용자가 선언한 변수나 배열 외에도 언어별로 사용된 라이브러리(헤더 파일, 모듈 등)와 운영체제에서 해당 프로세스에 할당한 메모리도 포함됩니다.
여러 쓰레드를 활용하여 문제를 해결하는 것도 가능합니다. 단, 프로그램에는 한 개의 CPU 코어만 할당되며, 시간 및 메모리 제한을 측정할 때 모든 쓰레드의 시간 및 메모리가 합산되어 측정됩니다.
채점 결과
각 제출에 대해 아래와 같은 결과 중 하나가 표시되며 각 결과에 대한 세부 내용은 다음과 같습니다.

CE (Compile Error) - 제출한 소스 코드의 컴파일에 실패한 경우입니다.
TLE (Time Limit Exceeded) - 제출한 소스 코드의 실행 시간이 문제에 명시된 시간 제한을 초과한 경우입니다.
WTLE (Wall Clock Time Limit Exceeded) - 제출한 소스 코드의 실제 실행 시간이 정해진 시간 제한을 초과한 경우입니다. 이는 프로세스가 CPU를 점유한 시간이 아닌 전체 실행 시간이 초과된 경우로, 실행 중 오류가 발생했을 수 있습니다.
RE (Runtime Error) - 실행 중에 오류가 발생한 경우입니다. 메모리 제한을 초과하거나 프로그램의 반환값이 0이 아닌 경우에도 이 오류가 발생할 수 있습니다.
WA (Wrong Answer) - 프로그램이 정상적으로 종료되었으나, 출력이 올바르지 않은 경우입니다.
IE (Internal Error) - 알 수 없는 내부 오류가 발생한 경우입니다. 이 결과를 받았다면 주최 측에 문의해야 합니다.
X승 (A/B/C) - 샘플 AI들과 대전한 결과입니다. 무승부를 0.5승으로 계산합니다.
만약 채점 결과가 여러 경우에 해당되는 경우 임의의 하나가 표시됩니다. 예를 들어, 프로그램이 실행 중 오류가 나면서 실행시간을 초과한 경우 결과는 RE 혹은 TLE 중 하나로 표시됩니다.

문제 관련 문의
문제에 틀린 내용이 있는 경우나 알 수 없는 내부 오류 등 대회 진행에 지장이 있는 경우 문제 페이지의 질문하기 버튼을 클릭하거나, 코딩 영역에서 Ctrl + K 단축키를 눌러 문의할 수 있습니다.

질문 내용에 비속어, 욕설 등 부적절한 표현이 포함되면 실격 처리될 수 있습니다.
문제 풀이 방법과 관련 질문에는 답변하지 않습니다.
유효하지 않은 질문 예시
아래와 같은 질문 유형은 대표적으로 유효하지 않은 질문에 해당합니다.

"제가 작성한 프로그램이 제 컴퓨터에서는 잘 나오는데 채점하니 결과가 정상적으로 나오지 않습니다."

제공된 테스트용 도구는 실제 채점 환경과는 차이가 있을 수 있습니다. 문제의 입출력 형식 등을 다시 한번 확인해주세요.
"제 컴퓨터에서는 컴파일이 잘 되는데 제출하니 컴파일 에러라고 나옵니다."

참가자가 사용하는 개발 환경과 실제로 프로그램이 컴파일되고 실행되는 채점 환경은 다를 수 있습니다. "개발 도구 사용 안내" 페이지를 반드시 확인해 주세요.
답변 유형
문제와 관련된 질문만 가능합니다. - 질문의 성격이 벗어난 경우에 해당합니다.
지문을 다시 읽어주시기 바랍니다. - 질문한 내용이 문제에 적힌 내용으로 충분히 답이 된다고 판단된 경우입니다.
답할 수 없습니다. - 영어로는 "No comment"에 해당하며, 주최 측의 답변이 어떠한 방식으로든 참가자의 문제 풀이나 대회 진행에 영향을 줄 수 있다고 판단된 경우입니다.
평가 규칙
샘플 AI 채점에서 특정 점수 이상을 받은 제출 중 한 개를 대표 답안로 선택할 수 있습니다.
선택한 대표 답안이 없다면, 샘플 AI 채점에서 특정 점수 이상을 받은 제출 중 가장 마지막 제출이 대표 답안으로 선택됩니다.
대표 답안은 대회 중 자유롭게 변경할 수 있으며, 대회 종료 후 1시간까지 변경할 수 있습니다.
대표 답안에 사용한 제출을 이용하여 중간 평가 및 최종 평가를 진행합니다.
연습 문제
중간 평가

예선 라운드 시작 전 매일 오후 9시 (KST), 각 팀이 제출한 코드 중 대표 답안으로 선택한 코드를 기준으로 평가를 진행합니다. 스위스 토너먼트 방식으로 최소 20 라운드를 진행하며, 해당 결과로 순위를 제공합니다.

연습 문제는 최종 평가를 진행하지 않으며, 최종 성적에 반영되지 않습니다.

예선 라운드
중간 평가

매일 오전 10시, 오후 3시, 오후 9시 (KST), 각 팀이 제출한 코드 중 대표 답안으로 선택한 코드를 기준으로 평가를 진행합니다. 스위스 토너먼트 방식으로 최소 20 라운드를 진행하며, 해당 결과로 순위를 제공합니다.

중간 평가는 참고용 결과이며, 최종 평가에는 영향을 미치지 않습니다.

최종 평가

스위스 토너먼트 방식으로 최소 50 라운드를 진행하여 상위 최소 100개의 팀을 선정합니다. 선정된 팀은 풀 리그 방식으로 모든 상대와 경기를 최소 5회 진행하여 최종 순위를 결정합니다.

본선 라운드
중간 평가

대회 시작 1시간 이후부터 최소 10회 이상 정해진 시점에 각 팀이 제출한 코드 중 대표 답안으로 선택한 코드를 기준으로 평가를 진행합니다. 대회 당일, 대회장에서 각 중간 평가에 대한 정보를 확인할 수 있습니다.

풀 리그 방식으로 모든 상대와 경기를 진행하며, 해당 결과로 순위를 제공합니다.

중간 평가는 참고용 결과이며, 최종 평가에는 영향을 미치지 않습니다.

최종 평가

모든 상대와 경기를 최소 5회 진행하여 각 상대와의 승수를 계산합니다. 수상자 결정 시 두 팀 승점의 차이가 근소한 경우 추가 경기를 진행할 수 있습니다.

평가는 다음과 같이 진행됩니다.

본선 참가자 모두를 대상으로 한 경기를 토대로 다른 모든 상대와의 승수 합이 가장 높은 상위 10팀을 뽑습니다.
상위 10팀을 대상으로 한 경기를 토대로 다른 모든 상대와의 승수 합이 가장 높은 상위 5팀을 뽑습니다.
상위 5팀을 대상으로 한 경기를 토대로 다른 모든 상대와의 승수 합이 가장 높은 상위 2팀을 뽑습니다.
상위 2팀을 대상으로 한 경기를 토대로 상대를 더 많이 이긴 팀을 최종 우승자로 선정합니다.
토너먼트 진행
토너먼트는 스위스 토너먼트 혹은 풀 리그 방식으로 이루어집니다. 스위스 토너먼트는 정해진 라운드 수만큼 라운드를 진행하며, 풀 리그는 한 라운드 안에서 모든 상대와 정해진 대전 횟수만큼 대전을 진행합니다.

시드 결정
시드는 이전 중간 평가의 등수에 따라 부여됩니다. (등수가 작을수록 작은 시드를 받습니다.)
첫 참가자 및 최종 평가의 경우, 제출 시간이 빠른 순서대로 작은 시드가 부여됩니다.
스위스 토너먼트 대전 상대 결정
1. 부전승 처리 (참가자 수가 홀수일 경우)

아직 부전승을 받은 적이 없는 참가자 중에서 선정됩니다.
해당 조건을 만족하는 참가자 중 점수가 가장 작은 사람이 선택됩니다.
여전히 동률인 경우, 시드가 가장 작은 참가자가 선택됩니다.
2. 대전 상대 매칭

점수가 큰 순서대로, 동일 점수 내에서는 시드가 작은 순서대로 매칭 상대를 찾습니다.
가능한 한 아직 대전하지 않은 상대와 매칭합니다.
여러 후보가 있는 경우, 점수가 가장 큰 상대를 우선 선택합니다.
여전히 동률이면, 시드가 가장 큰 상대와 매칭됩니다.
풀 리그 대전 상대 결정
모든 상대와 정해진 대전 횟수만큼 대전을 진행합니다.
경기 진행 방식
각 라운드에서 여러 경기가 동시에 진행됩니다.
선공/후공에 따른 차이가 있는 경우, 양측이 번갈아가며 선공/후공을 수행합니다.
점수 부여
경기 결과에 따라 다음과 같이 점수가 부여됩니다:

# NEXT NATION 룰북

이 문서는 NYPC 2026 Code Battle 예선 게임 `NEXT NATION`의 공식 규칙과 제공 로컬 테스트 툴
`nation-providing/testing-tool.py`를 기준으로 정리한 한국어 룰북이다.

봇 개선 시 이 문서를 우선 기준으로 삼는다. 특히 아래 네 가지는 전략 판단에 직접 영향을 준다.

- 하루 처리 순서는 `건설/업그레이드/수리 -> 이동 명령 비용/목표 설정 -> 훈련 비용/예약 -> 실제 이동 -> 훈련 전사 생성 -> 전투 -> 공성 적용 -> 노동 -> 보급`이다.
- 본부나 기지를 업그레이드하면 그 즉시 HP가 최대치로 회복된다.
- `UPGRADE`와 `TRAIN`을 같은 턴에 내면 업그레이드가 먼저 적용되므로, 그 턴의 훈련 한도와 훈련 전사 HP는 업그레이드 후 본부 레벨 기준이다.
- 200일 종료 또는 양쪽 본부 동시 파괴 시 승패는 본부 HP만 비교한다. 병력 수, 기지 수, 골드는 직접 점수에 들어가지 않는다.

## 1. 게임 개요

- 전장은 `0`번부터 `N-1`번까지 번호가 붙은 `N`개의 구역으로 이루어진다.
- 전장은 중심을 기준으로 점대칭이다.
- `LEFT` 플레이어의 본부는 `0`번 구역, `RIGHT` 플레이어의 본부는 `N-1`번 구역에 있다.
- 본부가 없는 구역 중 `K`개는 기지를 건설할 수 있는 거점이다.
- `N`과 `K`는 항상 홀수다.
- `51 <= N <= 109`이다.
- `ceil(0.15N) <= K <= floor(0.2N)`이다.
- 각 플레이어는 금화 `500`개와 본부에 있는 전사 `3`명으로 시작한다.
- 시작 전사 ID는 `LEFT`가 `A1`, `A2`, `A3`, `RIGHT`가 `B1`, `B2`, `B3`이다.
- 시작 본부는 레벨 `1`, HP `10`이다.
- 시작 전사 HP는 `4`이다.
- 게임은 최대 `200`일 동안 진행된다.

## 3. 건물

건물은 본부와 기지로 나뉜다.

- 건물은 자기 구역에 있는 아군 전사를 노동자로 사용해 저녁에 금화를 생산한다.
- 건물은 포탑 공격력을 가진다.
- 건물은 업그레이드되거나 수리될 때 HP가 최대 HP까지 찬다.
- 각 구역에는 하루에 `UPGRADE` 명령을 최대 한 번만 낼 수 있다.
- 따라서 같은 건물을 하루에 두 번 올리거나, 오늘 새로 지은 기지를 같은 날 다시 업그레이드할 수 없다.

### 본부

본부는 플레이어마다 하나뿐이다. 본부가 파괴되면 매우 불리하며, 상대 본부가 살아 있으면 패배한다.

| 레벨 | 해당 레벨이 되기 위한 비용 | 훈련 전사 HP | 본부 최대 HP | 포탑 공격력 | 하루 훈련 한도 | 노동 한도 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 없음 | `4` | `10` | `1` | `1` | `1` |
| 2 | `600` | `5` | `15` | `2` | `1` | `2` |
| 3 | `1200` | `6` | `20` | `2` | `2` | `3` |
| 4 | `2400` | `7` | `25` | `3` | `2` | `4` |
| 5 | `3600` | `8` | `30` | `3` | `3` | `5` |
| 5+ 수리 | `1000` | 없음 | 최대 HP로 회복 | 없음 | 없음 | 없음 |

표의 비용은 "그 레벨이 되기 위한 비용"이다.

- 레벨 1 본부를 레벨 2로 올리는 비용은 `600`이다.
- 레벨 2 본부를 레벨 3으로 올리는 비용은 `1200`이다.
- 레벨 3 본부를 레벨 4로 올리는 비용은 `2400`이다.
- 레벨 4 본부를 레벨 5로 올리는 비용은 `3600`이다.
- 레벨 5 본부에 `UPGRADE`를 내면 업그레이드가 아니라 수리이며, 비용 `1000`으로 HP가 `30`이 된다.

### 기지

기지는 거점에만 지을 수 있다. 본부와 달리 전사를 훈련하지 못한다.

| 레벨 | 건설/해당 레벨이 되기 위한 비용 | 최대 HP | 포탑 공격력 | 노동 한도 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | `300` | `6` | `1` | `1` |
| 2 | `600` | `12` | `1` | `2` |
| 3 | `1000` | `18` | `2` | `3` |
| 3+ 수리 | `500` | 최대 HP로 회복 | 없음 | 없음 |

기지 관련 주의점:

- 건물이 없는 거점에 `UPGRADE`를 내면 레벨 1 기지를 건설한다.
- 레벨 3 기지에 `UPGRADE`를 내면 업그레이드가 아니라 수리이며, 비용 `500`으로 HP가 `18`이 된다.
- 본부 구역에는 새 기지를 지을 수 없다.
- 적 건물이 있는 구역에는 `UPGRADE`할 수 없다.

## 4. 명령

매일 `START TURN T`를 받은 뒤 다음 형식으로 명령을 제출한다.

```text
COMMAND
MOVE A1 10
UPGRADE 5
TRAIN 1
END
```

명령은 원하는 만큼 낼 수 있다. 단, `TRAIN`은 하루에 한 줄 이하만 가능하다.

명령 줄의 순서는 전략적으로 의미가 없다. 실제 처리는 정해진 단계 순서대로 진행된다.

### MOVE

```text
MOVE <warrior_id> <target_region>
```

유효 조건:

- 자기 전사에게만 명령할 수 있다.
- 살아 있는 전사여야 한다.
- 현재 이동 중인 전사에게 새 `MOVE`를 내면 WA다.
- 같은 전사에게 같은 턴에 `MOVE`를 두 번 내면 WA다.
- 목적지는 `0 <= target < N`이어야 한다.
- 현재 구역에서 목적지까지 연결되어 있어야 한다.
- 비용을 낼 금화가 부족하면 WA다.

비용:

- 목적지에 아군 건물이 있으면 `0`.
- 그 외에는 `10`.

제공 테스트 툴 기준으로는 `UPGRADE`가 먼저 적용된 뒤 `MOVE` 비용을 계산한다. 따라서 같은 턴에 새 기지를 짓고 그 기지를 목적지로 `MOVE`를 내면, 그 이동은 무료가 될 수 있다.

공식 설명의 "금화를 소모하는 이동 명령을 내린 후 목적지에 기지가 건설되어도 환불되지 않는다"는 이미 비용이 `10`으로 확정된 이동이 나중 상태 변화로 환불되지 않는다는 뜻으로 보아야 한다. 반대로 무료 이동으로 확정된 뒤 목적지 건물이 파괴되어도 이동 명령은 중단되지 않는다.

### TRAIN

```text
TRAIN <n>
```

유효 조건:

- 하루에 `TRAIN` 줄은 최대 하나다.
- `n >= 0`이어야 한다.
- `n`은 현재 본부 레벨의 하루 훈련 한도 이하여야 한다.
- 비용 `120 * n`을 낼 금화가 있어야 한다.
- 본부가 이미 파괴되었다면 훈련할 수 없다.

중요한 처리 순서:

- `UPGRADE`가 먼저 처리되고 `TRAIN` 비용/한도 검사가 진행된다.
- 따라서 같은 턴에 본부를 레벨 2에서 3으로 올리고 `TRAIN 2`를 내면, 금화가 충분할 때 유효하다.
- 훈련 전사는 실제 이동이 끝난 뒤 본부 구역에 생성된다.
- 훈련 전사는 생성된 그날 전투에는 참여할 수 있다.
- 훈련 전사는 생성된 그날 이동할 수 없다. 이동 명령 처리는 훈련 전사 생성보다 먼저 끝난다.
- 전사 ID는 플레이어별로 `1`부터 증가하며, `A`는 `LEFT`, `B`는 `RIGHT` 소속이다.

### UPGRADE

```text
UPGRADE <region>
```

`UPGRADE`는 상황에 따라 건설, 업그레이드, 수리 중 하나가 된다.

유효 조건:

- 대상은 본부 구역 또는 거점이어야 한다.
- 대상 구역에 살아 있는 아군 전사가 최소 1명 있어야 한다.
- 대상 구역에 살아 있는 적 전사가 있으면 WA다.
- 같은 구역에 같은 턴 `UPGRADE`를 두 번 내면 WA다.
- 대상 구역이 본부 구역인데 건물이 없다고 해서 기지를 지을 수는 없다.
- 대상 구역에 적 건물이 있으면 WA다.
- 필요한 비용을 낼 금화가 없으면 WA다.

처리:

- 건물이 없는 거점이면 레벨 1 기지를 건설한다.
- 아군 건물이 있고 최대 레벨이 아니면 레벨을 1 올린다.
- 아군 건물이 이미 최대 레벨이면 수리한다.
- 업그레이드나 수리 후 HP는 즉시 최대 HP가 된다.

## 5. 하루 처리 순서

하루는 명령 제출 후 아래 순서로 처리된다.

1. 양쪽 플레이어가 명령 블록을 제출한다.
2. 시간 사용량을 계산하고 초읽기를 차감한다.
3. 명령 형식을 파싱한다.
4. `UPGRADE`를 처리한다.
5. `MOVE` 비용을 차감하고 이동 목표를 설정한다.
6. `TRAIN` 비용을 차감하고 훈련 수를 예약한다.
7. 이미 이동 중이거나 오늘 새로 이동 명령을 받은 전사들이 최대 한 칸 이동한다.
8. 예약된 훈련 전사가 본부에 생성된다.
9. 전투를 수행한다.
10. 공성 피해를 건물에 적용하고 HP 0 이하 건물을 파괴한다.
11. 노동으로 금화를 얻는다.
12. 보급 비용을 지불하고, 부족하면 전사가 굶주림 피해를 받는다.
13. 결과 블록이 양쪽 플레이어에게 전달된다.
14. 본부 파괴 여부 또는 200일 종료 여부에 따라 게임을 종료할지 판단한다.

제공 테스트 툴 구현상 `UPGRADE`, `MOVE`, `TRAIN`의 비용 검사는 한 플레이어의 명령 묶음 안에서 이 순서대로 일어난다. 즉 업그레이드로 금화를 쓴 뒤 남은 금화로 이동/훈련 비용을 낸다.

공식 설명은 아침을 `건설 단계 -> 이동 단계 -> 훈련 단계`로 표현한다. 현재
테스트툴 내부 구현은 `TRAIN` 비용과 수량 예약을 실제 이동 적용 전에 검사하지만,
훈련 전사 생성은 실제 이동 뒤에 수행한다. 이동과 훈련 비용 사이에는 수입·피해
처리가 없으므로 비용 가능 여부에는 관찰 가능한 차이가 없다. 전략적으로 중요한
부분은 `UPGRADE`가 먼저 적용되어 같은 턴 본부 훈련 한도/전사 HP와 새 기지
무료 이동 판정에 영향을 준다는 점이다.

## 6. 이동 규칙

전사는 `MOVE` 명령을 받으면 목적지에 도착할 때까지 이동 상태가 된다.

- 이동 중인 전사는 목적지에 도착하기 전까지 새 `MOVE` 명령을 받을 수 없다.
- 이동 중인 전사는 매일 이동 단계에서 최대 한 구역 움직인다.
- 현재 구역에 살아 있는 적 전사가 있으면 그날 이동하지 않고 멈춘다.
- 현재 구역에 적이 없으면 목적지까지의 최단 경로상 다음 구역으로 이동한다.

거리 계산:

- 인접한 두 구역 `u`, `v` 사이 이동 가중치는 두 중심 사이 유클리드 거리의 올림값이다.
- 즉 `ceil(sqrt((x_u - x_v)^2 + (y_u - y_v)^2))`이다.
- 현재 위치에서 목적지까지 이 가중치 합이 최소인 경로를 따른다.
- 최단 경로가 여러 개면 다음으로 이동할 구역 번호가 더 작은 쪽을 선택한다.

구현 체크:

- 모든 쌍 최단거리를 미리 계산해도 `N <= 109`라 충분히 가능하다.
- 단순 BFS hop 수가 아니라 유클리드 거리 합 최단 경로가 실제 이동 경로다.
- 전투로 길목에서 적과 마주치면 이동이 멈추므로, 도착 턴 예측에는 적 위치도 고려해야 한다.

## 7. 전투 규칙

전투는 이동과 훈련이 끝난 뒤, 낮 단계에 발생한다.

전투가 발생하는 구역:

- 한 구역에 양쪽 존재가 모두 있으면 전투가 발생한다.
- 존재에는 전사뿐 아니라 건물도 포함된다.
- 예를 들어 아군 기지만 있는 구역에 적 전사가 들어오면 전투가 발생한다.
- 아군 전사와 적 전사만 있고 건물이 없어도 전투가 발생한다.

공격 횟수 계산:

- 전투 시작 시점의 살아 있는 전사 수를 센다.
- 어떤 구역에서 내 전사 수가 `a`, 상대 전사 수가 `b`라면, 내 전사들은 총 `a`번 공격하고 상대 전사들은 총 `b`번 공격한다.
- 전투 중 HP가 0이 된 전사도 그 전투의 공격 횟수 계산에서는 이미 포함되어 있다.
- 즉 먼저 맞아 죽은 전사도 그날 자기 편 공격 횟수에 기여한다.
- 건물이 있는 쪽은 자기 전사 공격에 더해 포탑 공격을 수행한다.

공격 순서와 피해 원인:

- 건물이 있는 쪽은 포탑 공격을 먼저 수행한다.
- 포탑 공격 피해는 결과 로그에서 `DAMAGE TURRET`으로 기록된다.
- 전사 공격 피해는 `DAMAGE COMBAT`으로 기록된다.
- 제공 테스트 툴은 구역 번호 오름차순으로 전투를 처리하고, 한 구역 안에서는 `LEFT` 측 공격을 먼저 계산한 뒤 `RIGHT` 측 공격을 계산한다.
- 다만 양쪽 공격 횟수는 전투 시작 시점의 전사 수로 미리 정해지므로, 한쪽 전사가 먼저 HP 0이 되어도 그쪽 공격 횟수가 사라지지는 않는다.

각 1회 공격의 대상 선택:

1. 같은 구역에 HP가 1 이상인 상대 전사가 있으면 그중 HP가 가장 낮은 전사를 공격한다.
2. HP가 가장 낮은 상대 전사가 여러 명이면 번호가 가장 작은 전사를 공격한다.
3. HP가 1 이상인 상대 전사가 없고, HP가 1 이상인 상대 건물이 있으면 그 건물에 공성 피해 1을 준다.
4. 공격할 전사도 건물도 없으면 그 공격은 아무 일도 하지 않는다.

전투 종료 후:

- HP가 0 이하가 된 전사는 전장에서 제거된다.
- 건물에 들어간 공성 피해는 `SIEGE`로 기록된다.
- HP가 0 이하가 된 건물은 파괴된다.

전략상 중요한 예:

- 레벨 3 기지, 아군 전사 1명, 적 전사 2명이 같은 구역에 있다.
- 레벨 3 기지는 포탑 공격력 2라 먼저 적에게 2회 공격한다.
- 그 뒤 아군 전사 1명이 1회 공격한다.
- 적 전사 2명은 포탑과 전사 공격으로 HP 0이 되었더라도, 전투 시작 시점에 2명이었으므로 총 2회 공격한다.
- 적의 두 번째 공격 시점에 살아 있는 아군 전사가 없고 아군 기지가 있으면, 기지가 공성 피해를 받는다.

## 8. 노동과 보급

전투와 공성 적용 후 저녁 단계가 진행된다.

### 노동

- 각 건물마다 같은 구역에 있는 살아 있는 아군 전사를 노동자로 사용한다.
- 노동자 수는 `min(그 구역의 아군 전사 수, 건물 노동 한도)`이다.
- 노동자 1명당 금화 `15`를 얻는다.
- 한 전사는 하루에 한 건물에서만 노동한다.
- 한 구역에는 건물이 최대 하나뿐이므로 일반적으로 중복 노동 문제는 없다.
- 그날 새로 지은 기지도 저녁 노동 단계에 금화를 생산할 수 있다.
- 단, 기지를 지은 전사가 같은 턴 이동 단계에서 다른 구역으로 떠났거나 전투에서 죽으면 그 기지의 노동자가 부족할 수 있다.

### 보급

- 노동이 끝난 뒤 살아 있는 모든 자기 전사는 식비 `2`를 요구한다.
- 전사 번호 오름차순으로 식비를 처리한다.
- 금화가 충분하면 `2`를 지불한다.
- 금화가 부족하면 해당 전사는 HP를 1 잃는다.
- 굶주림 피해는 결과 로그에서 `DAMAGE HUNGER`로 기록된다.
- 굶주림으로 HP가 0 이하가 된 전사는 제거된다.

전략상 주의:

- 병력을 지나치게 많이 뽑으면 보급 비용 때문에 전사가 HP를 잃을 수 있다.
- 하지만 노동 수입이 먼저 들어오므로, 건물에 충분한 노동자가 있으면 보급 부담을 크게 줄일 수 있다.

## 9. 게임 종료와 승패

게임은 최대 `200`일까지 진행된다.

본부 파괴:

- 하루 처리가 끝난 뒤 어느 한쪽 본부가 파괴되어 있으면 게임이 종료된다.
- 한쪽 본부만 파괴되었으면 상대가 승리한다.
- 결과 사유는 `HQ_DESTROYED`다.

동시 본부 파괴:

- 같은 날 양쪽 본부가 모두 파괴될 수 있다.
- 이 경우 양쪽 본부 생존 여부가 같고 HP도 0으로 같으므로 무승부가 된다.
- 결과 사유는 `HQ_DESTROYED`다.

200일 종료:

- 200일이 끝났는데 양쪽 본부가 모두 살아 있으면 결과 사유는 `TURN_LIMIT`이다.
- 이때 승패는 본부 HP만 비교한다.
- 본부 HP가 더 높은 쪽이 승리한다.
- 본부 HP도 같으면 무승부다.

중요한 점:

- 200일 판정에서 전사 수, 기지 수, 금화, 상대 본부까지의 거리, 총 생산력은 직접 점수가 아니다.
- 다만 그런 요소들이 본부 HP를 지키거나 깎는 데 간접적으로 중요할 뿐이다.
- 레벨 5 본부 수리 `UPGRADE`는 200일 판정 직전에 매우 큰 의미를 가진다.

## 10. WA와 TLE

잘못된 출력이나 불가능한 명령은 즉시 WA가 된다.

대표적인 WA 원인:

- `COMMAND` 또는 `END` 형식을 지키지 않음.
- 알 수 없는 명령어를 출력함.
- `MOVE`, `TRAIN`, `UPGRADE` 인자 개수가 틀림.
- 존재하지 않는 전사를 이동시킴.
- 적 전사를 이동시킴.
- 이동 중인 전사에게 다시 `MOVE`를 냄.
- 같은 전사에게 같은 턴 `MOVE`를 두 번 냄.
- `TRAIN` 줄을 두 번 이상 냄.
- 훈련 한도를 초과함.
- 같은 구역에 같은 턴 `UPGRADE`를 두 번 냄.
- 거점도 본부도 아닌 구역에 `UPGRADE`를 냄.
- 적 전사가 있는 구역에 `UPGRADE`를 냄.
- 아군 전사가 없는 구역에 `UPGRADE`를 냄.
- 필요한 금화가 부족함.

양쪽 플레이어가 같은 턴에 동시에 유효하지 않은 명령을 제출하면 한쪽만
패배하지 않고 `DRAW WA`가 된다.

시간 제한:

- 초기 `READY` 입력을 받은 뒤 `OK`를 1000ms 안에 출력해야 한다.
- 매 턴 `START TURN T`를 받은 뒤 100ms 안에 `COMMAND ... END`를 출력하는 것이 기본 기준이다.
- 각 플레이어는 초읽기 토큰 `5`개로 시작한다.
- 100ms를 초과하면 초과 시간에 따라 초읽기가 줄어든다.
- 제공 테스트 툴 기준 차감량은 `ceil((사용시간 - 100) / 100)`이다.
- 남은 초읽기가 없는 상태에서 시간 제한을 넘기면 TLE로 패배한다.

로컬 테스트 툴 주의:

- 공식 HTML은 초읽기 소진 후 시간 초과를 `TLE`로 설명한다.
- 현재 제공 `nation-providing/testing-tool.py`는 명령 블록을 제한 시간 안에
  끝까지 읽지 못한 경우 최종 로그에 `WA`로 기록하는 경로가 있다.
- 따라서 로컬 로그의 `WA` 중 일부는 공식 판정상 `TLE`에 해당할 수 있다.
  봇 자체는 어느 쪽이든 시간 초과가 나지 않도록 관리해야 한다.

## 11. 인터랙션 프로토콜

### 준비 입력

```text
READY LEFT|RIGHT
N K
x_0 x_1 ... x_{N-1}
y_0 y_1 ... y_{N-1}
p_0 p_1 ... p_{K-1}
a_0 b_{0,0} ... b_{0,a_0-1}
...
a_{N-1} b_{N-1,0} ... b_{N-1,a_{N-1}-1}
```

의미:

- 첫 줄은 자신의 진영이다.
- `LEFT`면 내 본부는 `0`, 상대 본부는 `N-1`이다.
- `RIGHT`면 내 본부는 `N-1`, 상대 본부는 `0`이다.
- `x_i`, `y_i`는 `i`번 구역 중심 좌표다.
- `p_i`는 거점 구역 번호다.
- 각 구역 `i`에 대해 인접 구역 수와 인접 구역 번호 목록이 주어진다.

준비가 끝나면 반드시 출력한다.

```text
OK
```

### 턴 시작

```text
START TURN T
```

`T`는 오늘이 몇 번째 날인지 나타낸다.

### 명령 제출

```text
COMMAND
...
END
```

명령이 없어도 `COMMAND`와 `END`는 출력해야 한다.

### 결과 입력

```text
TURN T
TIME T_x R_x T_y R_y
UPGRADE N
<side> <region>
...
TRAIN N
<warrior_id_1> ... <warrior_id_N>
MOVE N
<warrior_id> <region>
...
DAMAGE N
<cause> <warrior_id> <damage>
...
SIEGE N
<side> <region> <damage>
...
END
```

섹션별 의미:

- `TIME`: 이번 턴에 자신과 상대가 쓴 시간, 남은 초읽기.
- `UPGRADE`: 이번 턴 건설, 업그레이드, 수리된 건물 목록.
- `TRAIN`: 이번 턴 새로 생성된 전사 ID 목록.
- `MOVE`: 이번 턴 실제로 한 칸 이동한 전사와 도착 구역 목록.
- `DAMAGE`: 전사가 받은 피해 목록. 원인은 `TURRET`, `COMBAT`, `HUNGER`.
- `SIEGE`: 건물이 받은 피해 목록.

주의:

- `TRAIN N`에서 `N = 0`이면 다음 ID 줄이 없다.
- 다른 섹션도 `N = 0`이면 뒤따르는 줄이 없다.
- 제공 테스트 툴은 결과를 정렬해 보낸다. `UPGRADE`와 `SIEGE`는 구역 번호
  오름차순, `MOVE`와 `TRAIN`은 전사 번호 순, `DAMAGE`는
  `TURRET -> COMBAT -> HUNGER` 순서 뒤 전사 번호 순이다. 이 정렬은 로그
  표시 순서일 뿐 하루 처리 순서를 바꾸지 않는다.
- 공식 HTML 전문은 "각 턴의 결과는 `END` 명령어로 마무리됩니다"라고
  명시하며, 제공 테스트 툴도 결과 블록 끝에 `END`를 보낸다. 현재 봇은
  이 구현에 맞춰 `END`를 읽는다.
- 게임이 끝나면 `FINISH`가 온다.
- `FINISH`를 받으면 추가 결과를 읽으려 하지 말고 즉시 정상 종료해야 한다.

## 12. 전장 생성 규칙

전장 구조는 게임 시작 입력으로 주어지므로 봇이 반드시 생성 규칙을 직접 구현할 필요는 없다. 그래도 랜덤 맵 대응과 로컬 테스트를 위해 생성 규칙을 알고 있으면 좋다.

상수:

| 이름 | 값 |
| --- | ---: |
| `L` | `10000` |
| `D` | `100` |
| `A` | `24` |

생성 요약:

1. `N'`을 `25` 이상 `54` 이하에서 무작위로 고른다.
2. `N = 2N' + 1`이다.
3. `K'`를 허용 범위에서 무작위로 고른다.
4. `K = 2K' + 1`이다.
5. 원점 중심 반지름 `L`인 원 안에서 격자점을 뽑아 점 집합 `P`를 만든다.
6. 점을 뽑을 때 기존 점과 `x`좌표가 같거나 거리가 `D` 미만이면 다시 뽑는다.
7. 점 `u`를 추가할 때 원점 기준 점대칭점 `u'`도 같이 추가한다.
8. `x`좌표 오름차순으로 구역 번호를 붙인다.
9. 보조 점 집합 `Q`를 원점 중심 반지름 `1.5L` 원 위에 `A = 24`개 만든다.
10. `P ∪ Q`로 보로노이/델루네 계산을 하고, `P`의 보로노이 다각형 무게중심으로 `P'`를 만든다.
11. `P' ∪ Q`로 다시 보로노이/델루네 계산을 해서 인접 관계를 만든다.
12. 중앙 구역 `N'`은 항상 거점이다.
13. 거점은 점대칭 쌍으로 추가된다.
14. 새 거점 후보 `t`와 그 대칭점 `N-1-t`가 기존 거점과 인접하면 다시 뽑는다.
15. `t`와 `N-1-t`가 서로 인접해도 다시 뽑는다.

로컬 테스트 툴에서 `--NP`, `--KP`를 지정할 때:

- 실제 `N = 2 * NP + 1`이다.
- 실제 `K = 2 * KP + 1`이다.
- `--NP`와 `--KP`는 함께 지정해야 한다.

with open("data.bin", "rb") as f:

## 15. 봇 설계 체크포인트

룰에서 바로 나오는 구현 체크리스트다.

- `UPGRADE`와 `TRAIN`을 같은 턴에 같이 낼 수 있다. 업그레이드 후 훈련 한도를 활용할 수 있다.
- 기지 건설 후 같은 턴 노동 수입을 얻으려면, 그 구역에 아군 전사가 저녁까지 살아서 남아 있어야 한다.
- 목적지가 아군 건물이면 이동 비용이 0이다. 내 건물 간 이동은 경제적으로 매우 중요하다.
- 이동 경로는 hop 최단이 아니라 유클리드 거리 합 최단이다.
- 적과 같은 구역에 있으면 이동이 멈춘다. 길목 차단이 가능하다.
- 전투 시작 시점의 전사 수가 공격 횟수를 결정한다. 먼저 죽어도 그 전투의 공격권은 사라지지 않는다.
- 포탑은 낮은 HP 전사를 잘 마무리한다. 번호가 낮은 전사는 같은 HP일 때 먼저 맞는다.
- 본부 레벨업은 HP 회복, 포탑 증가, 훈련 HP 증가, 훈련 한도 증가, 노동 한도 증가를 동시에 준다.
- 레벨 5 본부 수리는 200일 판정에서 직접 승패를 바꿀 수 있다.
- 200일 판정은 본부 HP만 본다. 막판에는 병력 생산보다 본부 HP 보존/수리/상대 본부 피해가 더 중요할 수 있다.
- 금화가 부족한 상태에서 과도한 병력을 유지하면 번호가 낮은 전사부터 굶주림 피해를 받는다.
- `FINISH`를 받으면 즉시 종료해야 한다. 결과 블록이 올 것이라 가정하고 더 읽으면 안 된다.
